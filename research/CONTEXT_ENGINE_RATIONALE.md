## 1. مقارنة أطر الذاكرة — لماذا حلّ مخصّص لا إطار جاهز؟

الطلب: ذاكرة طويلة الأمد (محادثات + ملفات + تفضيلات) **تتجاوز نافذة الموديل** عبر تخزين خارجي + تلخيص + استرجاع ذكي. قُيّمت 4 خيارات + الأنماط مقابل قيودنا (anti-bloat، إعادة استخدام Postgres، 6GB→سحابة، حياد الموديل/الواجهة عبر hook، عربي، HITL).

**مصفوفة الدرجات (1–5 لاحتياجاتنا):**

| البُعد | Mem0 | Zep/Graphiti | Letta/MemGPT | **Custom Hybrid** |
|---|:--:|:--:|:--:|:--:|
| ملاءمة الأنواع الـ3 | 3 | 3 | 5 | **5** |
| التاريخ الطويل (تلخيص+استرجاع) | 2 | 3 | 5 | **5** |
| جودة الاسترجاع | 4 | **5** | 4 | 4 |
| بساطة البنية | 4 | 2 | 3 | **5** |
| إعادة استخدام Postgres | 5 | 1 | 4 | **5** |
| ملاءمة 6GB | 3 | 2 | 2 | **5** |
| النضج | **5** | 4 | 4 | 3 |
| قابلية التبديل | 4 | 3 | 2 | **5** |

**الأحكام (السبب الحاسم لكلٍّ):**
- **Mem0** (Apache-2.0، pgvector first-class، ناضج): ❌ **لا يلخّص التاريخ الطويل** (V3 ADD-only، يخزّن "حقائق ذرّية" لا نصوصاً — يفقد جوهر الطلب)؛ **لا نوع ملفات**؛ نداء LLM لكل كتابة (ثقيل على 6GB). → ممتاز لـ **ذاكرة المستخدم** فقط، لا كمحرّك التاريخ الطويل.
- **Zep/Graphiti** (أقوى استرجاع: رسم معرفي زمني + multi-hop): ❌ **يتطلّب قاعدة رسم منفصلة** (Neo4j/FalkorDB — يخرق "أعد استخدام Postgres")؛ **5–6 نداءات LLM لكل رسالة** (وثائقه تحذّر من الموديلات الصغيرة)؛ نسخة المنصّة self-host (CE) أُلغيت 2025. → **مؤجَّل للسحابة**، نستعير أفكار الاسترجاع فقط.
- **Letta/MemGPT** (أفضل ملاءمة مفاهيمية للأنواع الثلاثة + التلخيص التلقائي عند 90%): ❌ **انقلاب معماري** — Letta **يملك حلقة الـ agent ويصير الواجهة الأمامية**، ليس hook خلف LiteLLM ولا نقطة `/v1` بلا-حالة → يكسر مبدأ حياد الموديل/الواجهة ويُنزّل بوّابتنا لمجرّد backend؛ lock-in عالٍ؛ كثير النداءات على 6GB؛ المنتج يتّجه لـ "Letta Code". → **أفكاره ممتازة، شكله خاطئ لنا.**
- **Custom Hybrid** 🏆: أعلى ملاءمة لكل قيودنا، وهو **تطوّر تصميمنا القائم** (L1 يعمل أصلاً). الثمن الوحيد: **نبنيه ونصونه** (نضجه = اختباراتنا). قابل لإدخال إطار لاحقاً (Mem0 لحقائق المستخدم / Graphiti للرسم الزمني) **خلف نفس الواجهة** إن برّر القياس.

**الخلاصة:** "أفضل ذاكرة" ليست منتجاً بل **معمارية = نظام ذاكرة متدرّج (Memory OS)**. قيودنا الصارمة تستبعد Zep (قاعدة رسم) وLetta (انقلاب)، وMem0 يفشل في جوهر التلخيص → **Custom Hybrid هو الوحيد الذي يرضيها جميعاً**.

## 2. ورشة التصميم — المراجعة العدائية: حقائق صادمة وقرارات مقفلة

11 خبيراً صمّموا، و5 مراجعين عدائيين كشفوا أن التصميم المُجمَّع كان **متضخّماً لـ v1** + حقائق حرجة. أهمّها:

**حقائق صادمة (غيّرت المسار):**
1. **نافذة Gemma الحقيقية = 4096** (ناقص ~2048 للجواب) → ميزانية الحقن الفعلية **مئات–~1500 توكن** فقط. المعمارية صحيحة ومستقبلية، لكن الفائدة المرئية متواضعة حتى موديل أكبر. الأمثلة "5M→18k" رؤية لا واقع اليوم.
2. **`postgres:16-alpine` لا يملك pgvector** → أي متجهات تتطلّب تبديل الصورة (يعدّل تثبيت digest في P-01) → **ADR-020، خطوة صفر**.
3. **هوية المستخدم (`X-OpenWebUI-User-Id`) غير موثوقة** (مفتاح OWUI مشترك) → أي RLS بلا قيمة دونها؛ بوّابتنا الداخلية = الحدّ الأمني المقبول لـ v1.
4. **RLS بلا فائدة إن اتّصلت الخدمة كـ owner** (تتجاوز RLS) → يلزم role split + FORCE + WITH CHECK = enterprise لـ 1–10 مستخدمين → **مؤجَّل v2** (نأخذ المكاسب الرخيصة الآن).
5. **بُعد التضمين غير مثبّت** + halfvec(N) شبه أحادي-الاتجاه → **نقيس قبل أي DDL** (تبيّن = 1024).
6. **التلخيص بـ LLM يزاحم Gemma على 6GB** ("async ≠ غير-مُزاحِم" بمحرّك واحد) → **مؤجَّل v2**؛ v1 = التقاط حرفي + استرجاع (الفصل عن النافذة محقَّق بالاسترجاع لا التلخيص).

**القرارات المقفلة (حلّ 18 تعارضاً بين المصمّمين):**
1. **3 جداول لكل-مصدر** (لا STI واحد)؛ Normalize = مُحوِّل `native_row→MemoryItem`؛ المراحل لا ترى شكل المخزن.
2. عقد واحد **`MemoryItem`** (Pydantic)؛ `embedding_ref` وصف لا متجهات خام؛ dedup عبر قناة جانبية أو content_hash؛ `provenance` كائن مُهيكَل.
3. مفردات موحّدة: `user_id` مفتاح العزل · `bigserial` PK + `item_id` · enum حالة موحّد · `content↔text` يُوحَّد في Normalize.
4. **pgvector = خطوة صفر** (ADR-020)؛ bootstrap يفشل بصوت لا stack-trace.
5. **تثبيت البُعد** قبل أي ALTER؛ مُصدَّر بالإصدار (تغييره = عمود v2 + backfill).
6. **النافذة 4096:** إلزام `model_info.max_input_tokens` + tokenizer حقيقي + تأكيد `injected+reserved ≤ window` (نُسقِط الأدنى ترتيباً، لا نعتمد على قصّ المحرّك). — **صحّحه ADR-021** (تدقيق 2026-06-26): نافذة من الإعداد + عدّ توكنات = بايتات UTF-8 (محافظ مُثبَت) + fail-open؛ هذا القرار الأصلي (model_info + tokenizer حقيقي + fail-fast) مؤجَّل v2.
7. **الأمان v1:** `WHERE user_id` + بوّابة داخلية + provenance + حذف-للنسيان + اختبار عزل على Postgres حقيقي. RLS الكامل + virtual keys per-user + تجريد header = **v2 إلزامية قبل أي فتح خارجي**.
8. **التلخيص مؤجَّل v2**؛ v1 محادثة = التقاط حرفي + استرجاع دلالي.
9. **seam كتابة واحد** = `ingest` موحّد؛ inline-async (بلا طابور/worker v1)؛ `POST /v1/memories` يبقى shim.
10. **`normalize_ar` واحدة** مُصدَّرة بالإصدار (فهرسة = استعلام بايت-بايت).

**الحارس الشامل (anti-bloat):** v1 = حاوية embeddings واحدة جديدة + أعمدة على جداول قائمة + صفر workers + صفر roles جديدة + كل شيء وحدات داخل خدمة `memory`. "ابدأ بسيطاً، قِس، ثم وسّع."

## 3. المؤجَّل لـ v2 (صراحةً، خلف نفس العقود)
التلخيص بـ LLM + High/Low-Water · RAPTOR/هرمي · parent/child + Excel-row + إصدارات الملفات · **RLS كامل + virtual keys per-user + تجريد header (إلزامية قبل أي فتح خارجي)** · Reflection memory (استنتاجات الموديل، بثقة أقل، خلف بذرة `MemoryItem`) · LLM router · ضغط/دمج بـ LLM · طابور كتابة دائم.

> **المبدأ:** كل مؤجَّل قابل للإضافة دون إعادة تصميم لأن العقود (`MemoryItem`، خط الأنابيب، الـ hook) ثابتة — "نفس الشكل، صناديق أكبر".
